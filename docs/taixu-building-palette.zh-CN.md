# 太虚造化天枢：建筑、结构管理与预览

> 悬于太虚，摄诸天之精；运转造化，衍万物之形。

这一版提供 14 种可放置的建筑方块、独立原生像素材质、模型、连接纹理和核心特效。
在模组创造物品栏中可以找到全部部件，也可以用 `/give @s molecularmanipulator:taixu_creation_nexus` 获取控制器部件。
已接入 97×97×129 的完整蓝图、多方块检测、JEI 分层预览、世界投影、自动搭建与回收界面。
本版的资源采集、复制、生产库存接口和生存合成配方尚未启用；资源接口仍是预留建筑部件。

## 放置与使用

1. 放置控制器后右键打开界面。新版控制器和四个接口内嵌在中央固定圆台前缘，不再生成外侧平台。
   建筑最低点在控制器下方 65 格，最高点在其上方 63 格；默认世界中控制器 Y 应为 1～256。
   推荐选址预留 113×113×145 的空域。旧版独立平台建筑继续按原蓝图识别，不会自动改动存档。
2. JEI 中对控制器查看配方，或查看其用途，即可打开结构页。支持全部 / 单层、拖拽旋转、平移、缩放与视角复位。
3. 界面的“结构材料”页展示 12 种材料总量和当前待补数量；旧版蓝图另含楼梯，共 13 种材料。
   待补数只统计已加载区域，方块朝向错误另计为冲突。
4. “结构投影”只显示未完成的方块；红色表示冲突，也会标出中央光柱空间中的障碍。再次点击关闭。
5. “自动搭建”自底向上施工，最多每 tick 放置 64 个方块。生存模式优先消耗背包，再从直接连接的 ME 网络提取；
   ME 连接需要供电及 1 个频道，控制器待机耗电 4 AE/t。创造模式免材料。
6. 缺料、区块未加载、权限保护、玩家离线 / 离开维度时等待；处理后自动重试。可暂停、继续或终止，进度与回收缓存随存档保存。
7. “回收结构”需要三秒内再次点击确认。仅回收当前蓝图匹配的方块，按层自顶向下进行，保留控制器与外部装饰。
   材料优先返回 ME，再进入背包；空间不足时保存在界面左下方的回收槽，暂停后续拆除，直到取走材料或腾出空间。

建筑包含三层环带、八座塔簇、中央开放式天轴和一枚衍生核心，共 **14,665** 个方块（含控制器）。
JEI、投影、检测、搭建和材料页共用 `TaixuStructure` 蓝图。强制加载沿用模组的多方块配置；关闭时等待玩家加载所需区块。

### 旧建筑迁移至中央

完全退出并重启客户端后，在旧控制器总览页点击“内嵌控制器”，并留在控制器附近。
运动中的三环八塔先归位，再迁移控制器和四个接口，移除旧平台及台阶。
建筑的世界坐标、核心、环带和塔柱位置保持一致，无需整座回收重建。
成功后将操作者送到已有中央走道，旧平台消失不会让操作者跌落。

生存模式返还 40 个玉壳、10 个楼梯、3 个台阶，共 53 个方块；控制器、接口和原回收缓存直接转移。
材料依次进入新位置可用的 ME 网络、背包和回收槽；装不下的部分持久保存在控制器内，可分批取走。
创造模式不发放拆除材料。外部 ME 线缆需要在新控制器位置重新连接。
迁移检查施工权限，放置被保护事件拒绝时恢复原建筑与缓存。

新版蓝图控制器坐标为 `(0,65,-7)`；四个接口位于 `(-3,65,-6)`、`(-2,65,-6)`、
`(2,65,-6)`、`(3,65,-6)`，均为固定部件。旧版控制器坐标为 `(0,39,-34)`。
旧版共 14,718 个方块，玉壳 2,782、楼梯 10、台阶 948，其余材料数量同新版。

## 实体运动与乘载

完整成型后，点击“启动运动”，三层环带与八座塔柱转换为 11 个具有实际碰撞的运动实体。
玩家和普通实体可以站在环面或塔柱平台上，随旋转和升降移动；跳起后脱离乘载。
不需要安装额外运动模组。运动需要启用模组现有的 `server.force_load_chunks` 配置；关闭后会暂停。

- 三环自下而上以 +1.6、-2.2、+1.2 度/秒旋转（20 TPS），方向交错。
- 八塔最大上下偏移各 1.5 格，16 秒一个周期，相位错开，启动前三秒平滑起浮。
- “暂停运动”保持当前位置与碰撞；“继续运动”沿原进度继续。
- “部件归位”把环带与塔柱缓慢送回蓝图位置，恢复为可正常编辑的方块。运动时不能直接挖掘组件。
- 运动路径有外来障碍时暂停，清理后点击继续；归位遇阻会保持位置，清理后自动续接。
  归位遵守放置权限，拒绝时回滚本次放置并保留材料。存档保存当前相位和归位进度。
- 运动中选择“回收结构”，会先归位再按原回收流程拆除。
- 拆下运动中的控制器，会将其持有的运动部件材料打包进一个控制器物品。
  重新放置并右键打开后，材料按 ME、背包、回收槽顺序返还；背包满时可分批取走。

运动组件复用原生 16×16 方块材质和组内连接纹理。实体网格缓存后，每帧只更新变换矩阵。
旋转边缘采用细分的保守碰撞盒，边缘有小幅近似；结构内部的空洞保持可穿行。
全景观察建议将视距设为 16 个区块，保证远处组件处于客户端实体追踪范围内。
动态特效等级可以关闭装饰光效，实际运动实体仍然显示并参与碰撞。

### Sodium Extras 距离裁剪兼容

Sodium Extras 1.0.8 的实体距离裁剪按实体原点计算，而三环八塔的原点位于建筑底部中心。
其默认 32 格纵向阈值会把眼前的巨型运动组件隐藏，表现为点击“启动运动”后三环八塔消失。
客户端启动时，现在通过该模组自己的配置追加两条精确白名单：
`molecularmanipulator:taixu_assembly`（实体）和 `molecularmanipulator:taixu_creation_nexus`（方块实体）。
其他距离裁剪选项、阈值和原有白名单保持不变；没有安装 Sodium Extras 时不执行集成。
该模组会缓存类型检查结果，更新 JAR 后需要完全退出并重启客户端。

## 材质与特效

全部材质由 `tools/textures/generate_taixu.py` 在 16×16 网格上从零绘制，未读取或缩放其他建筑的贴图。
珍珠白与淡金为正常受光表面，冰蓝能量独立自发光。16 张静态材质搭配 10 张独立发光动画。
动画 PNG 为 16×384 的帧条，每帧仍为 16×16；24 帧、每帧 2 tick、帧间插值，周期 2.4 秒。

衍生核心的镂空笼架包含晶体、两道倾斜旋转光环、轨道光点和双螺旋流光。
动态几何始终位于核心的一格范围内，受正常遮挡和视锥裁剪控制；不会透过墙壁显示。
客户端 `visual.dynamic_effect_level` 为 0 时关闭动态几何与阵眼粒子，1 时降低细节；
2 时启用完整近景效果。24 格外降低细节，48 格外停止核心动态渲染。原生材质动画仍由 Minecraft 图集播放器控制。
成型后由控制器统一绘制整座建筑的仪式光效，采用原生位置/颜色几何，无需外置光影包：

- 太虚天仪中央八瓣分面晶簇、上下浮晶、十二枚环绕碎晶、金纹约束笼架、三道倾斜星轨和扩散共振波。
  中央天轴保留金蓝螺旋与升腾晶光，晶簇之间留有空隙。
- 三环内外双色轨道、原创菱形符纹、分段垂落光幕和渐隐流星尾迹；下环向内汇聚、中环竖立约束符纹、
  上环释放升腾晶光。全部装饰跟随实体的实际旋转角。
- 八塔顶端双层八芒法阵、尖端光束、底端支撑法阵、沿塔身爬升的光脉，以及向中央汇聚的弧形传导光流。
  塔顶与塔底法阵同步读取实际升降偏移，暂停或归位时不会与实体脱节。

启动运动时，客户端读取运动实体的实际累计进度，约八秒内依次展开塔阵、三环与中央晶簇。
暂停时能量亮度和流速平滑降低，恢复时平滑增强；加载已运行的建筑不会重播启动。
晶体表面采用带深度写入的半透明层，光带使用保留遮挡、不写深度的加法层；两层均关闭背面裁剪。

整座建筑的光效不生成额外粒子实体，保留深度遮挡。完整档使用约 55,000 个顶点，
简化档约 13,000 个顶点（包含晶体表面）；`visual.dynamic_effect_level=1` 或距核心超过 224 格时降低段数并省去部分装饰。
等级 0 关闭装饰几何，实际结构与实体碰撞仍然工作。光效包围盒涵盖全部光束、尾迹和升降极值。
控制器负责服务端施工与检测；衍生核心只有客户端特效，不执行服务端 Tick。其他建筑部件不产生 Tick 开销。

## 连接纹理

使用模组内置的连接模型，不依赖外部连接纹理模组。

- 玉壳移除同平面内部接缝；玻璃合并边框，内部连接处的金色固定角也会消失。
- 金纹块移除内部接缝与重复角饰，保留中央纹饰和真正的外轮廓。
- 环轨按横向光路、立柱和导流柱按纵向纹理连接；旋转后依据实际烘焙 UV 方向判断，不跨接垂直的纹路。
- 控制器、阵眼、稳定器和接口保留各自中心图标；相同侧面材质可以连接。
- 缺少对角邻居时保留凹角，遮挡面不会误连。楼梯和台阶仅在完整、共面的方形表面参与连接，半面与阶梯边缘保留原形状。
- 物品栏模型保持单个方块的外观；资源重载后重建连接缓存。

## 维护与验证

使用 Python + Pillow 和 Java 21：

```powershell
python tools/textures/generate_taixu.py
.\gradlew.bat --no-configuration-cache -I tools/textures/verify.init.gradle verifyTaixuTextureAnimations verifyTaixuModels
python tools/textures/verify_taixu.py
.\gradlew.bat --no-configuration-cache -I tools/gametest/taixu.init.gradle runGameTestServer
.\gradlew.bat --no-configuration-cache build
```

预览输出到已忽略的 `build/taixu-palette/`，不会打入模组 JAR。
`taixu-blocks.png`、`taixu-connected.png` 和 `taixu-core.gif` 使用 Minecraft 原生烘焙顶点及实际核心特效几何，
在隔离的 OpenGL 环境中展示；固定灯光、无场景光照，不是运行中游戏的截图。
`taixu-textures.png` 和 `taixu-textures.gif` 为像素材质展示。

GPU 检查使用原生图集动画播放器核对完整循环；原生模型检查覆盖所有 79 个模型变体和连接面。
隔离服务端同时检查整座旋转搭建、材料清单一致性、生存取料、权限回滚、暂停重载、拆除恢复、回收背压，
以及真实 AE 网络的频道供电、背包优先、ME 精确取料 / 回收、离线等待与未加载区块检查。
实体运动检查覆盖环带和塔柱乘载、跳离、障碍暂停、归位冻结与重载、权限回滚，以及控制器实际掉落后的精确材料回收。

真实客户端验证脚本为 `tools/ui/taixu-client.init.gradle`，只使用 `build/taixu-client-run/saves/` 中复制的隔离测试世界。
运行前将 `build/taixu-regression-run/world` 复制到该目录的新子目录（例如 `TaixuUIFresh`），然后执行：

```powershell
.\gradlew.bat --no-configuration-cache -I tools/ui/taixu-client.init.gradle -PtaixuUiWorld=TaixuUIFresh runClient
```

客户端验证覆盖界面、JEI、投影、成型渲染、昼夜光效及生存玩家不按移动键的实际乘载。
可额外加载整合包的六个渲染模组，检查 11 个运动体的实体追踪及真实渲染分发器裁剪结果；
运行方式见 `tools/ui/README.md`。新增特效单元测试核对顶点数量、有限坐标、包围盒、时钟循环、
矩阵恢复及环塔光纹与实体变换一致性。
`taixu-ui-*.png`、`taixu-jei.png`、`taixu-world-*.png`、`taixu-ring-rider.png` 为实际客户端截图；
`taixu-structure-native.png` 是固定灯光的独立模型预览。测试源不进入发行 JAR。
