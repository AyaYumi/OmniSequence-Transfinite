# 分子构序重写阵列

## 用途：一块方块，存配方并实际制作

把**样板**——在样板编码终端里写好配方的卡片——放进重写阵列，再从 ME 终端下单，它就会在内部完成合成、锻造或切石。无需在旁边再放分子装配室。

左边是设备，右边是它能执行的三类样板：合成、锻造、切石。需要熔炉等外部机器的**处理样板**请放进样板供应器，不放在这里。

先分清三个位置：**合成 CPU**是接单、安排制作顺序的设备；**重写阵列**保存做法并动手制作；**ME 存储**存放原料和成品。重写阵列不能代替前后两者。

## 准备

- 在[构筑井](matter_fabrication_research.md)完成一轮**Ⅲ阶：构序工程**。
- 让[星算引擎](star_computation_engine.md)达到 **L3**，在研究页主动点击解锁**单方块集成**。费用为 **0 bit**，达到等级后仍要点击解锁。默认该节点只限制本设备和超限算枢的制作配方。
- 一个已供电的 ME 网络，带物品存储、终端、可接单的合成 CPU，以及 **1 个空闲频道**。频道就是网络留给联网设备的连接名额。
- 一张已编码样板，以及这张配方实际需要的原料。

## 步骤：先做一单木板

1. 放下重写阵列，用 ME 线缆接入上述网络。
2. 在样板编码终端制作一张“橡木原木 → 橡木木板”的合成样板，把它放进重写阵列的样板槽。
3. 向 ME 存入至少 **4 个橡木原木**，并为产物留下存储空间。
4. 在 ME 终端找到橡木木板的合成入口，请求制作 **16 个**，选择可用的合成 CPU 并确认。
5. 打开合成状态界面，等待订单完成，再从终端取出木板。

样板库共有 **360 槽**，分成 **10 页，每页 36 槽**。换配方时用翻页按钮找空位，也可通过同网络的样板管理终端整理。

## 成功标志

- 终端能找到样板对应的可合成物品。
- 测试订单完成，ME 中少了 4 个原木、多了 16 个木板。
- 设备负责实际制作，CPU 不再等待这份配方的产物。

大单会按可用材料、能源和接收空间执行。可批量的配方会合并制作； 容器和工具按实际配方返还，耐久照常变化。 同网络的星算引擎可提高制作并行量； 构筑井的深度研究只提高井内对应配方的并行， 不提高这台设备的制作速度。

## 排错

| 看到的情况 | 怎么处理 |
| --- | --- |
| 终端没有这件可合成物品 | 确认放入的是已编码的合成、锻造或切石样板，设备有电且取得频道。 |
| 能选物品，却没有可用 CPU | 给同一网络接入空闲合成 CPU；重写阵列本身不接订单。 |
| 订单一直等材料 | 看合成状态中的缺料；需要外部加工的步骤要有样板供应器和对应机器。 |
| 已制作却不回库 | 给 ME 腾出容量，并检查存储是否允许接收该物品。产物和返还物会留在设备里等待接收。 |
| 构筑井显示配方锁定 | 同时检查井内“构序工程”和“单方块集成”许可；借用联网许可时，提供许可的星算引擎要保持在线。 |

取消订单会停止未执行的部分，返还未用原料；已经做出的成品仍会保留并等待交付。

## 下一步

- 样板越来越多：使用[构序阵列](sequence_array_controller.md)集中管理大样板库，它也内置制作功能。
- 想让常用物品自动补满，而不是每次下单：使用[分子自动合成器](molecular_auto_crafter.md)。
- 大单超出 CPU 的接单能力：了解[万物演算核心](omni_computation_core.md)。

搬迁前先结清订单。正常拆下设备时，样板和未完成内容随方块携带； 重新放下并恢复网络与供电后可继续。
